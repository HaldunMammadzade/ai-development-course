# Personalized learning path

The path is a server-owned reading of the published curriculum. It does not own the curriculum.

```text
Curriculum
  → prerequisites
  → mastery and assessment evidence
  → personalized path
  → adaptive learning
  → next action
```

There is no student path table, no path snapshot, and no AI call. Each catalog request builds the path from the lessons, prerequisite edges, mastery rows, lesson progress, and the current adaptive focus that the catalog already loaded.

## Placement

`buildPersonalizedPath` walks published lessons in module and lesson order.

A lesson is credited when either:

- its progress is already `completed`, or
- every primary concept is at or above the existing unlock threshold and `isLessonUnlocked` is true.

The threshold is `UNLOCK_MASTERY` (60). This step does not add a score, a percentage, a weight, or a confidence formula. A lesson with no primary concepts is not credited by mastery. A mastered lesson that is still locked is not credited and is not opened.

The current step is the first published lesson that is not credited and is unlocked. The next list is at most three later lessons that are neither credited nor fully known. Known-but-locked lessons stay out of that list. They remain visible as known concepts.

`getNextAction` uses the same credit rule after due homework and an open session. It still stops at the first locked lesson. It does not jump to a later module.

Lesson availability follows that result. The next-action lesson is current. A credited lesson is completed. Every other lesson is locked.

## Concept-level path

The concept list is the current module’s primary concepts, in lesson order, at most eight rows around the current concept.

A concept is known only when its mastery score is at or above the same unlock threshold. An unknown concept is not shown as known. A weak concept (`score < 45` and at least two evidence rows, the existing `isWeak` rule) is marked for review unless it is the current step.

Known names are capped at eight: known concepts in the current module, up to four later known concepts, and the four known concepts closest to the current lesson. That is how a later React concept can be acknowledged while the current step remains the missing prerequisite.

## Prerequisite gap

Assessment evidence does not infer a missing earlier concept. The hole from the initial assessment stays a hole:

```text
HTML and CSS known
  → web.javascript unknown
  → a later concept such as js.function, TypeScript, React, or Next.js known
```

`web.javascript` is the primary of `js-basics` and is not on an assessment item. The current step stays `js-basics` until that concept reaches the existing threshold and the lesson is unlocked. Lessons whose primaries are already known, such as the function lesson, are not listed as the next study steps. They stay locked until their own prerequisites are met. The path says: “Bu mərhələyə keçmək üçün bir əsas mövzu qalıb.”

When the missing concept later reaches the threshold, the next request credits the unlocked lesson and moves the current step. Nothing is regenerated by hand.

## Adaptive learning

Adaptive focus does not reorder lessons and does not bypass unlock. It only adds a sentence:

- remediation or re-explain: “Əvvəl bu əsas mövzunu möhkəmləndirək.”
- review, retry, or hint: “Bu mövzunun əsaslarını əvvəlcə möhkəmləndirək.”

A foundation gap takes precedence over that sentence. Decision names are not sent as the note and are not rendered.

## Assessment and returning students

On a completed assessment, the result page loads the same catalog path. The starting lesson, the known names, and the first link come from that path. Gaps still come from the assessment result, which only lists concepts that were actually answered.

A student who already has lesson progress, a teaching session, an exercise attempt, or a non-quiz learning event is `not_required` and is not sent back to the assessment. Their path is progress, mastery, and adaptive focus.

Student preferences store explanation style and challenge level only. There is no stored learning goal, daily time, or experience field. The path does not read preferences, and a stated goal cannot skip a prerequisite.

## Dashboard and projects

The dashboard hero remains the real next action. When the catalog includes a path, the dashboard shows that short list instead of a completed/total count of every lesson.

Project eligibility is unchanged. It still depends on concept mastery for the project’s required concepts. The dashboard can say “Layihəyə yaxınsan” when a project already has passed milestones and is not finished. That sentence does not unlock the project.

## Security

The client does not submit a path, a lesson order, a completion, a mastery value, or a start lesson. The assessment answer schema is strict and rejects those fields. Opening a session does not accept a lesson slug. A direct URL whose catalog availability is locked does not load exercises and does not open a teaching session. The page shows the locked state and a link to the current legal lesson. The exercise list already returns not found unless the lesson is current or completed.

## Performance

The path is an in-memory walk of the catalog’s existing lesson, prerequisite, and mastery arrays. It does not query mastery again, read a transcript, call a model, search vectors, or use Redis, WebSockets, or server-sent events.

## Accessibility

The path is an ordered list. The current concept has `aria-current="step"` and a visible status word. Color is not the only status. The current lesson link and the locked-lesson action are at least 44px tall and have a visible focus ring. Module details use the native disclosure. The path does not animate.

## Testing

Curriculum tests cover a beginner, strong HTML/CSS, strong JavaScript, strong React with a JavaScript gap, a mixed profile, a mastery change, a returning student’s progress, a challenge decision that does not skip ahead, and remediation copy without the internal decision name. Catalog tests cover credit and availability. The answer schema and the assessment HTTP tamper case reject an injected path, completion, mastery, and start lesson. The lesson-access test rejects a locked slug. Screen tests cover the dashboard path and the assessment result.

## Known limitations

- Crediting a lesson whose progress is `completed` does not mark its concepts known. Concept marks come only from mastery.
- The minimum path through an unassessed chain still includes the lessons whose concepts were never evidenced. Those lessons are the legal prerequisite chain. They are not replaced with invented mastery.
- A due homework item or an open teaching session still wins `getNextAction` before the path walk. The path’s current step remains the first legal uncredited lesson.
- Preferences cannot personalize order because goal, time, and experience are not stored.
- The path does not change project gates.
